# 100 颗回忆星 · 使用与维护说明

一个纯前端的小站点：100 颗星对应 100 条回忆，逐颗点亮、写下回应、飞进许愿瓶，最后在银河里回看。

---

## 一、文件结构

```
memories/
├── index.html    页面（结构 + 样式 + 交互逻辑，全部在这一个文件里）
├── data.js       素材 + 配置（你以后只需要改这个文件）
├── README.md     本说明
└── deploy.sh     一键重新部署脚本
```

没有框架、没有构建步骤，双击 `index.html` 就能在本地看效果（数据用 `file://` 也能加载）。

---

## 二、换素材：只改 data.js

打开 `data.js`，把 `window.MEMORIES` 里的示例文字替换成你们的真实素材：

```js
window.MEMORIES = {
  1: '第一条回忆的原文……',
  2: '第二条……',
  7: '编号可以跳号，缺号的地方页面上就是一颗几乎看不见的空位。',
  36: '……'
};
```

规则很简单：

- **键是编号，值是原文**，一个字都不要让程序改；
- 编号 1–100 之间**可以缺号**，缺号渲染为「待补充空位」，不会被当成星星；
- 补齐素材后重新部署即可，**旧的本地进度会自动清空**（页面用素材内容算哈希，内容一变就重置，避免和旧素材错位）。

---

## 三、改冷却时长：改一个数字

`data.js` 里：

```js
cooldownMinutes: 5   // 测试期 5 分钟；上线可以改成 60、720（12 小时）等
```

改完重新部署，所有人刷新后生效。冷却期间：

- 所有未点亮的星变暗、不可点；
- 底部显示「下一颗星 04:32 后可点亮」的倒计时；
- 已点亮的星仍然可以点开回看。

> 冷却记在访问者自己的浏览器里（localStorage），换设备/清缓存会重新计时——这是纯前端方案的天然边界，也符合「不做账号系统」的设定。

---

## 四、重置与查看

- **重置本机进度**：网址后面加 `?admin=1`，右下角会出现管理面板，点「重置进度」。
- 面板里还能看到：已点亮数量、当前素材包含哪些编号、导出进度 JSON（备份用）。
- 普通访问者看不到这个入口。

## 五、交互与动效说明（为什么这样设计）

| 环节 | 做法 | 理由 |
|---|---|---|
| 点亮 | 星位绽开一圈光 + 合成音效（两个正弦波，无音频文件） | 只在这一刻给「高光」，其他动效都收敛 |
| 阅读 | 原文**逐字出现**（32ms/字），点文字可立即显示全部 | 模拟「有人慢慢讲给你听」，又不强迫等待 |
| 回应 | 提交后显示「你已经和星星一块生成新的回忆碎片啦」+ 回应时间 | 给一个明确的情绪落点，再把星送进瓶子 |
| 入瓶 | 星星沿弧线飞向许愿瓶，瓶内多一颗 | 让「收集」这件事看得见 |
| 背景 | 深紫渐变 + 极暗微尘，可点的星是四角星 | 背景没有任何亮点与可点星同形，避免「点错」 |
| 引导 | 首访文字提示 5 秒后淡出 + 随机星星轻微闪烁 | 不打断，只提示一次 |
| 减少动效 | 跟随系统 `prefers-reduced-motion`，关闭飞行/闪烁/绽放 | 尊重系统设置 |

## 六、部署（链接固定不变）

**线上地址：https://yokim99.github.io/memory-stars/**

托管在 GitHub Pages（仓库 `yokim99/memory-stars`，`main` 分支每次推送自动发布）。改完素材后：

```bash
cd memories
./deploy.sh
```

脚本会先检查 `data.js` 语法，然后自动 `git commit + push`。**大约 1 分钟后刷新页面即可看到新内容，链接不变。**

备用方案：Surge（域名 `100-memory-stars.surge.sh` 已发布，但账号需要点一下邮件里的验证链接才能访问）：

```bash
export SURGE_LOGIN='...' SURGE_TOKEN='...'
./deploy.sh surge
```

> 想换域名/换托管：把 `index.html` 和 `data.js` 两个文件放到任意静态托管即可，页面不依赖后端。

### 本地预览

```bash
cd memories
python3 -m http.server 8080
# 打开 http://localhost:8080
```

## 七、隐私与边界

- 回应与进度**只存在访问者自己的浏览器**，不上传、不收集、没有后端；
- 同一台设备清理浏览器数据会丢失进度；
- 任何人拿到链接都能看内容、写自己的回应（各自的浏览器各存各的）；
- 仓库是公开的（GitHub Pages 免费版要求），素材原文也会随仓库公开；
- 素材会随页面公开，请只放你们愿意被看到的内容。

---

## 八、常见问题

**Q：改了素材，为什么进度没清空？**
A：哈希基于 `data.js` 里 `MEMORIES` 的内容计算，只有内容真的变了才会重置；只改冷却时间不会清进度。

**Q：冷却能不能对同一个人永久生效？**
A：不能。纯前端只能记在浏览器里，换设备/无痕模式会重置。要更强约束就需要后端账号体系。

**Q：手机能玩吗？**
A：可以，已做响应式：小屏星星缩小、卡片铺宽、许愿瓶固定在左下角。
